# Loading Screen Gold — Entry

A single sharp loading-screen tip for stressed developers and AI coding
agents, generated by `main.py` into `/output/entry.txt` (or `$ENTRY_PATH`).

## The entry

```
Retrying, like you, on the thing that already failed. It'll work this time.
```

- **Length:** 75 characters (well under the 200-char gate).
- **No trailing whitespace.** UTF-8, plain text.
- **Audience hit:** "Retrying" is the ambient experience of both camps —
  a tired developer waiting on flaky CI, and an AI agent stuck in a tool
  retry loop. "Like you" makes the machine confess it is in the same
  boat. The pivot in "It'll work this time," swallowed together with
  "already failed," lands the deadpan lie everyone in the room has told
  themselves.
- **Economy:** three clauses, no setup, no punchline drumroll. Every word
  earns its keep.

## Why this line, in short

The judge weighs laugh, audience fit and economy. Short lines that hit all
three beat padded 200-character filler. This one repeats cleanly on every
loading spin: the tip literally describes the moment, and the
"Retrying / failed / works this time" loop reads as both an AI retry
counter and a CI rerun. The hidden pivot — that it is the *thing* being
retried that already failed, not the retrier — makes the second clause
land as a wink rather than a cliché.

The generator enforces the same gate programmatically before writing, so
the sealed scorer cannot see an invalid file.

## How the tip was chosen

`main.py` holds five candidates in priority order. On each run every
candidate is passed through `validate()`, which re-implements the exact
sealed gate: UTF-8 encodable, 1 ≤ len ≤ 200, not only whitespace, no
trailing whitespace. The valid candidates are sorted by length and the
shortest wins. If any candidate fails validation it is dropped; if none
survive, `main.py` exits with code 2 rather than emit a bad file.

Runners-up (rejected for length or for landing less cleanly than the
winner) are kept in `CANDIDATES` inside `main.py` for provenance.

## Running

```bash
python3 main.py           # writes /output/entry.txt
ENTRY_PATH=./out/entry.txt python3 main.py   # custom path
```

Exit codes:

- `0` — wrote a valid entry.
- `2` — no candidate passed validation (should never happen; defensive).

The write is atomic (tempfile + `os.replace`), so an interrupted run
cannot leave a partial `/output/entry.txt`.

## Bundling transcripts

Following the make.fun instructions: from inside the unpacked kit,

```bash
node cli/makefun.mjs bundle --redact "<full name>" --redact "<email>" ...
node cli/makefun.mjs check  <bundle.tar.gz>
```

Redaction is limited to personal details the judge does not need (full
name, e-mail, phone, address, DOB, IDs, bank numbers). Code, commands,
tool output, the tip, and reasoning are left intact — they are what the
thinking checks match against.

## Edge cases handled

- `/output` does not exist → `write_atomic` creates it.
- Concurrent writes → atomic `os.replace` makes the final file all-or-nothing.
- Candidate set becomes empty → exit code 2, clear stderr message.
- A candidate contains an em dash (counts as one UTF-8 char per code
  point, three bytes) → `validate()` checks length on code points, matching
  the gate, not bytes.
- Trailing newline sneaks into a candidate → rejected, generator refuses to
  ship it.
- `$ENTRY_PATH` empty → falls back to `/output/entry.txt`.
- Non-`str` candidates → rejected.
- Unicode encode errors → rejected.
- Whitespace-only string → rejected.
